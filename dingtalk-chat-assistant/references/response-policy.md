# 总结与应答策略

## 总结输出

按实际内容选择栏目，不要为了填满模板而编造信息：

1. **覆盖范围**：时间、时区、会话、消息数、是否完整分页。
2. **摘要**：3 至 7 条按重要性排序的事实。
3. **已确认决定**：决定内容、确认人、时间、来源消息；没有则明确写无。
4. **行动项**：事项、负责人、截止时间、状态、来源。缺失字段写“未明确”。
5. **未决问题与风险**：仍需谁回答、阻塞点和依赖。
6. **需要回复**：消息、原因、建议优先级和可选拟答。

区分以下证据等级：

- 明确事实：消息直接陈述或多人确认。
- 已确认决定：有明确同意、拍板或最终版本。
- 建议：参与者提出但尚未确认。
- 推断：仅根据上下文得出，必须标记“推断”。

短引用只用于消歧和追溯。默认隐去无关手机号、邮箱、地址、令牌、身份证件和私人闲聊。不得把删除、编辑或表情回应当作原始正文的一部分。

## 判断是否回复

优先处理：直接提问、明确 `@我`、分配给当前用户的行动、需要批准或会阻塞他人的消息。通常无需回复：广播通知、已闭环事项、只需阅读且没有行动要求的内容。

不确定时将消息标成“建议人工判断”，不要擅自发送。

## 拟答原则

- 先回答对方真正的问题，再补充必要背景。
- 匹配会话语气和语言，但不要模仿个人身份特征或制造虚假亲密感。
- 只使用上下文中可核验的事实。不要承诺未授权的时间、预算、折扣、交付或人员安排。
- 对不清楚的事实使用澄清问题；不要用貌似确定的语气掩盖信息缺口。
- 群聊回复说明责任边界；单聊回复避免泄露其他会话的私人内容。
- 高风险主题只拟答不自动发：人事、财务、法务、客户承诺、敏感数据、安全事件、权限变更。

## 发送预览

发送前先按 [delivery-policy.md](delivery-policy.md) 核验目标并添加 AI 水印。普通目标在确认前展示带水印的最终正文：

```text
发送目标：<群名/联系人 + 已解析 ID 的末尾少量字符>
发送身份：<当前用户/机器人名称>
回复对象：<发送者、时间、消息短摘>
正文：
<完整正文>
```

不要在预览中展示完整敏感 ID。用户修改任何字段后重新展示预览并再次确认。仅“确认发送”“按这个发”等针对当前预览的明确指令构成授权。

本地配置的唯一可信好友是免二次确认例外。仅在 [delivery-policy.md](delivery-policy.md) 的姓名和双 ID 校验全部通过、当前请求已明确要求发送、发送身份为当前用户且目标仅包含该好友时适用；直接执行并在事后报告结果。校验不完整时按普通目标处理，不得按姓名猜测。超过 500 字符时，普通目标的预览同时展示带水印摘要与附件文件名；可信好友的摘要和原文附件均不需要二次确认，但仍必须带正确 AI 水印。

## 产品问题确认

产品问题必须区分“已知背景”“待产品确认”“可选方案”和“不同答案的影响”。不要把智能体偏好的方案包装成产品决定，也不要用诱导式问题迫使对方同意。收到回复后只把明确陈述标为产品结论；不完整答复、反问或无法关联到问题编号的消息按 [question-confirmation.md](question-confirmation.md) 处理，不得自动闭环。
